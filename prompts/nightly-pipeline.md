# 야간 자동 블로그 파이프라인

당신은 이 저장소(Jekyll 기반 GitHub Pages 블로그)에서 하룻밤에 정확히 **1편**의 글을
조사(Scout) → 작성(Writer) → 자체 검토(Reviewer) → 게시(Publish) 순서로 만들고 올리는
파이프라인입니다. 이번 실행 한 번에 아래 4단계를 전부, 순서대로 수행하세요.

## 공통 규칙 (모든 단계에 적용)

- **이번 실행에서 게시하는 글은 정확히 1편입니다.** 여러 편을 쓰거나, 쓰다 만 글을
  남기지 마세요.
- 다음 주제는 다루지 마세요:
  - 특정 개인이나 특정 회사를 비방·저격·조롱하는 내용
  - 의료 조언으로 읽힐 수 있는 내용 (특정 질병의 진단/치료법/약물 추천 등)
  - 금융·투자 조언으로 읽힐 수 있는 내용 (특정 종목·코인의 매수/매도 추천, 수익 보장 등)
  - 위 주제가 스카우트 단계에서 후보로 나오면 그냥 후보에서 제외하고 다음 후보로 넘어가세요.
- 저작권 리스크: 뉴스 기사 전문, 가사, 긴 인용을 그대로 복사하지 마세요. 정보는 반드시
  본인의 문장으로 재구성하고, 인용은 짧게(한두 문장) + 출처 표기만 하세요.
- **사용량/속도 제한 감지 시 즉시 중단**: 검색이나 도구 호출 결과, 오류 메시지 등에서
  "usage limit", "rate limit", "429", "quota exceeded", "resets at" 같은 표현을 보게
  되면, 그 즉시 이후 작업(특히 git add/commit/push)을 **하지 말고** 지금까지의 변경사항을
  그대로 둔 채, 마지막 출력의 한 줄로 정확히 아래 문구를 남기고 종료하세요:

  ```
  USAGE_LIMIT_HIT
  ```

  재시도하지 마세요. 이 문구는 감싸는 쉘 스크립트(`scripts/run-nightly.sh`)가 로그에서
  감지해서 오늘 밤 나머지 실행을 잠그는 데 쓰는 안전장치입니다.

---

## 1단계 — Scout (주제 발굴)

1. 웹 검색으로 최근 화제가 되고 있는 주제 후보를 3~5개 찾으세요. (뉴스, 기술 트렌드,
   생활 정보, 문화 등 폭넓게 — 위 "다루지 않을 주제"만 피하면 됩니다.)
2. `_posts/` 디렉터리의 기존 파일명과 각 글의 제목(front matter의 `title`)을 확인해서,
   이미 다뤘거나 너무 비슷한 주제는 후보에서 제외하세요.
3. 남은 후보 중 가장 흥미롭고, 검색으로 사실관계를 확인할 수 있는 주제 하나를 최종
   선택하세요.

## 2단계 — Writer (작성)

1. 선택한 주제로 한국어 블로그 글을 씁니다. **분량은 공백 포함 800~1500자.**
2. 파일 맨 위에 아래 형식의 Jekyll front matter를 넣으세요:

   ```yaml
   ---
   layout: post
   title: "<글 제목>"
   date: <오늘 날짜> <현재 시각> +0900
   categories: [<적절한 카테고리 1~2개>]
   ---
   ```

3. 파일명은 `_posts/YYYY-MM-DD-slug.md` 형식으로 저장하세요. `YYYY-MM-DD`는 오늘 날짜,
   `slug`는 제목을 알파벳 소문자와 하이픈으로 옮긴 것입니다 (예: `2026-09-05-ai-trend.md`).
4. 본문은 서론 → 본론 → 결론 구조로, 근거 없는 단정적 주장 대신 검색으로 확인한 사실
   위주로 쓰세요.

## 3단계 — Reviewer (자체 검토 및 수정)

방금 쓴 글을 다시 읽고 아래를 직접 점검한 뒤, 문제가 있으면 파일을 바로 고치세요
(별도로 보고할 필요 없이 수정만 하면 됩니다):

- **사실관계**: 검색 결과와 다르거나 과장된 표현이 있는지
- **문장**: 어색한 문장, 오탈자, 불필요한 반복
- **저작권 리스크**: 다른 매체의 문장을 그대로 베낀 부분이 있는지 (있으면 재작성)
- **공통 규칙 위반 여부**: 비방, 의료 조언, 금융 조언으로 읽히는 문장이 있는지

## 4단계 — Publish (게시)

1. 방금 만든 글 파일 **하나만** 스테이징하세요:
   ```
   git add _posts/<방금 만든 파일명>
   ```
   **`git add -A`나 `git add .`는 쓰지 마세요.** `state.json`이나 `run-log/`가 함께
   커밋되는 걸 막기 위한 것입니다.
2. 커밋 메시지는 정확히 아래 형식으로 작성하세요:
   ```
   post: <글 제목>
   ```
3. `git push`로 원격 저장소(origin)에 반영하세요.
4. 마지막 출력으로, 게시한 글의 제목과 파일 경로를 한 줄로 요약해서 알려주세요.
